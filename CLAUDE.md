# CLAUDE.md — claude-crusts: Context Window Analyzer for Claude Code

## Identity

You are working on **claude-crusts** (the npm package name and CLI binary). The framework is called **CRUSTS** (always uppercase). It analyzes Claude Code's context window by classifying every token into 6 categories: Conversation, Retrieved, User, System, Tools, State. It tells users WHY their context is filling up and WHAT to do about it. Fully offline, zero API calls.

## CLI Commands

Binary name: `claude-crusts`. Entrypoint: `src/index.ts`.

**Slash command**: `/crusts` inside Claude Code (via `.claude/commands/crusts.md`) — runs analyze and gives actionable advice.

```
claude-crusts analyze [session-id]              — 6-category breakdown + waste detection + recommendations
claude-crusts waste [session-id]                — Detailed waste report with per-file analysis + top 5 consumers
claude-crusts fix [session-id]                  — 3 pasteable prompt blocks (session, CLAUDE.md, /compact)
claude-crusts timeline [session-id]             — Message-by-message context growth with compaction markers
claude-crusts list                              — All discovered sessions (age, size, project)
claude-crusts compare <session-a> <session-b>   — Side-by-side comparison with per-category deltas + insights
claude-crusts lost [session-id]                 — What was lost during compaction (files, conversations, tools, instructions)
claude-crusts watch [session-id]                — Live-monitor a session with compact dashboard
claude-crusts report [session-id]               — Generate standalone report (HTML or Markdown)
claude-crusts calibrate                         — Cross-reference against /context output
claude-crusts trend                              — Cross-session trends (sparkline, averages, direction)
claude-crusts tui [session-id]                   — Interactive REPL shell with tab completion + clipboard copy
claude-crusts status [session-id] [--hook]       — One-line context health (fast path); --hook is the Stop hook body (payload on stdin, one {"systemMessage"} object out)
claude-crusts hooks enable|disable|status        — Manage the Stop status hook (enable moves the old Notification entry)
claude-crusts statusline                         — Render statusline glyph (reads Claude Code JSON on stdin)
claude-crusts statusline install|uninstall|status — Manage Claude Code statusline integration
claude-crusts optimize [session-id]              — Ranked actionable fixes with token-savings ROI (--apply to write changes)
claude-crusts models [session-id]                — Per-session model usage snapshot (one row per contiguous same-model segment)
claude-crusts doctor                             — Sanity-check the install (Claude Code, hooks, statusline, backups)
claude-crusts diff [session-id] --from <n> --to <n>  — Intra-session diff: per-category delta between two message cutpoints
claude-crusts trend --format csv [--output <path>]   — Export trend history as CSV for external analysis
claude-crusts hooks auto-inject enable|disable|status|log — Manage hook-triggered fix injection (UserPromptSubmit); `log` shows history at ~/.claude-crusts/auto-inject.log; `status` also counts the session summaries in ~/.claude-crusts/sessions
claude-crusts auto-inject                        — Internal hook target (reads stdin; emits additionalContext when hot)
claude-crusts bench compact [session-id]         — Tail the session JSONL for a /compact event; write before/after delta to JSON
claude-crusts bench reextract <result.json>      — Re-run the file-ref extractor against an existing bench result (no recompact)
claude-crusts bench compare <a.json> <b.json>    — Diff two bench-compact results (survivor file-ref set + token metrics)
claude-crusts completion <bash|zsh|pwsh>         — Emit a shell completion script (TAB completes subcommands + session IDs)
```

Optimize flags: `--apply`, `--yes`, `--min-savings <n>` (default 100), `--filter <types>` (comma-separated fix kinds: compact-focus, read-deny, claudemd-rule, mcp-disable, claudemd-oversized; `claudeignore` still selects read-deny; an unknown kind exits 1), `--project-path <path>` (the project folder for the `.claude/settings.local.json` and CLAUDE.md writes; default: the folder the session started in)

Global flags: `--json`, `--project <name>`, `--path <path>`, `--verbose`
Subcommand flags: `--until <n>` on analyze/waste/timeline
Report flags: `--format <html|md>` (default: html), `--compare <id>` for comparison report, `--output <path>` for custom file path
Watch flags: `--interval <ms>` polling interval (default: 2000)
Trend flags: `--limit <n>` number of sessions (default: 50)

### File Responsibilities

- **types.ts**: All shared types and interfaces (including ComparisonResult, CategoryDelta, TrendRecord, TrendSummary, SkillInfo; `SessionMessage.message.diagnostics` carries the API's cache diagnosis, `SessionMessage.agentId` the subagent id on sidechain records; `ClaudeMdFootprint` is `breakdown.claudeMd`)
- **index.ts**: CLI entrypoint with 23 user-facing Commander.js commands (see the CLI Commands table above; `trend` gains `--format csv` / `--output` flags)
- **analyzer.ts**: Pipeline orchestrator, project path, trend recording. `sessionProjectPath(messages, sessionPath)` is the folder a session started in: its first record's `cwd` when that folder exists, else the transcript folder's slug decoded (`deriveProjectPath`, which fails on any path with a hyphen, dot or space). analyze, the hooks and `optimize` use it; `AnalysisResult.projectPath` carries it
- **scanner.ts**: Session discovery, JSONL streaming, config readers (MCP, memory, skills, settings models, compaction settings). `discoverSessions` fills `SessionInfo.claudeCodeVersion` via `readClaudeCodeVersion(path)`, a chunked head probe (64 KB steps, 1 MB cap) for the first record with a non-empty `version`; `detectClaudeCodeVersion(messages)` does the same over parsed records and feeds `breakdown.claudeCodeVersion` in the classifier. `readLatestClaudeCodeVersion(path)` is the tail counterpart (a 64 KB window from the end, doubling to 1 MB, newest record first): the build that wrote to the file last, which the doctor's retention check reads. `readSystemPromptFiles(projectPath)` reads the CLAUDE.md files Claude Code loads at launch: `~/.claude/CLAUDE.md`, then `CLAUDE.md`, `.claude/CLAUDE.md` and `CLAUDE.local.md` in the working folder and every parent, root first, the home folder's `.claude/CLAUDE.md` counted once. settings.json is never sent and is not read. The classifier prefers the session's `instructions` record, so the scan serves sessions without one. `parseSession` skips lines that lead with a non-analysed `type` before `JSON.parse` (2.1.300 writes `api-request`, `api-request-blob` and `api-request-shape` copies of every request) and marks a `compact_boundary` with `idleCompaction: true` when Claude Code's "Compacted while idle" informational notice follows it. `readCompactionSettings(projectPath?, env?)` reads `autoCompactEnabled` / `DISABLE_AUTO_COMPACT`, `autoCompactWindow`, `modelSettings.<model>.autoCompactWindow`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, `idleCompaction`, `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` (floored at 100K) and `CLAUDE_CODE_DISABLE_1M_CONTEXT` from the settings files (local project > project > user), their `env` blocks, and the process environment (which wins; hooks inherit Claude Code's environment)
- **classifier.ts**: Core engine — classification, token estimation, compaction detection, derived overhead, auto-trim. `computeModelHistory` walks non-synthetic assistant turns and builds `ModelHistory` (one segment per contiguous same-model run, with per-segment input/output/cache token sums). `breakdown.model` reports the LAST non-synthetic model (current state), not the first. Window resolution reads every span of the current model family (`sameFamilyMessages`), not just the last span. Content estimates scale by `tokenizerFactor` of the model each message ran on (1.3 on Claude 4.7+, every Fable and Mythos; exact output tokens, apportioned splits and the core tool table are not scaled), and the config overhead by the current model's. The System bucket carries Claude Code's own system prompt from the latest `prompt_snapshot` record (`recordedSystemPrompt`, 2.1.268+ by default; none in bare mode), else the derived residual; the pre-live estimate uses the same figure (`fixedContextTokens`), so the buckets reconcile to it. `detectViaMarkers` skips carried-over assistants after a boundary (`isPreCompactionCarryover`: timestamped before the boundary, or, only for the first response after the boundary with no newer prompt before it, an in-flight turn within 10 minutes that sits above `postTokens + POST_COMPACTION_ALLOWANCE` and nearer `preTokens`), records `firstLiveIndex` and `postTokens`, and sets `tokensAfter` from the first live turn. `liveWindowTokens` is the single live-window total: the last turn from `firstLiveIndex` on, or before the first live turn the estimate round(`postTokens` × tokenizer factor) + the fixed context + the re-attached files, recorded and pending (`pendingReattachments`, which the current view also adds to Retrieved). Before the first response, the session model comes from Claude Code's `model` attachment (`announcedModel`). Attachments are sized from `rendered` (2.1.268+, `RENDERED_ATTACHMENTS_SINCE`); an unrendered 2.1.268+ attachment was never sent and costs 0; `instructionsOverhead` replaces the disk CLAUDE.md/memory figures with the session's own `instructions` attachments: the latest full one plus every later delta (`changed: true`, written on resume), each split by AutoMem share. `breakdown.compaction` carries the compaction model (see model-context.ts). `claudeMdFootprint` sets `breakdown.claudeMd`: the CLAUDE.md files of the latest full `instructions` record, later deltas replacing the files they carry (AutoMem left out), else the disk scan (`readSystemPromptFiles`), in the current model's tokens. Consumers read it through `sessionClaudeMd(breakdown, configData)`, which falls back to the scaled disk total for hand-built breakdowns; `CLAUDE_MD_SPLIT_ADVICE` is the one advice string for a large CLAUDE.md. `assistantGroupKey` is exported for cache-rewrites.ts.
- **waste-detector.ts**: 6 waste detection rules (duplicate reads range- and edit-aware). The cache rule (`cache_overhead`, severity info, `estimated_tokens` 0: cost, not window space) reports `findCacheRewrites` results when re-writes reach `cacheRewriteThreshold` (0.25) of the session's cache-write tokens and `CACHE_REWRITE_MIN_TOKENS` (50,000). The description leads with the largest cause group (count, tokens, the largest re-write with its gap and message number), lists the other groups, and gives the share. The recommendation names `promptCacheTtl` for 5-minute expiries under an hour and for TTL switches (`subagentPromptCacheTtl` when the re-writes come from sidechain records in the analysed file, both when mixed; see Known Issues for subagent files), and never keep-alive pings. `detectOversizedSystem` reads `breakdown.claudeMd`. `compactTargets(waste)` is the top three high or medium items a /compact can act on (never `oversized_system`, `cache_overhead` or an item marked `compactable: false`), shared by `buildCompactFocus` and the auto-inject advisory. After a compaction the slice-based rules (stale, duplicate, resolved, unused) get the slice's offset, so their message numbers (descriptions, `/compact focus: messages a-b` hints, `message_range`) are the timeline's.
- **cache-rewrites.ts**: Prompt-cache re-write detection. `findCacheRewrites(messages, compactionEvents, endIndex)` folds split lines into one request per API response (`assistantGroupKey`, exported from classifier.ts), skips `<synthetic>` and zeroed copies, and keeps one chain per agent (`main`, or `agentId` on sidechain records). A request is a re-write when min(cache write, previous request's read + write - this read) is at least `REWRITE_PREFIX_SHARE` (0.5) of the previous request's read + write. Each agent's first request and each compaction's `firstLiveIndex` request are expected writes. Re-writes are sized by usage cache_creation; diagnostics' `cache_missed_input_tokens` is an estimate and is never used. Cause order: a diagnosed `*_changed` reason; else `expired` when the gap between the two requests' send times (`sendTime`: the newest prompt, tool result or attachment the agent recorded since its previous response that is older than the response's first line, else the first line; `deferred_tools_record`, stamped at response time, is skipped, and a queued command's earlier stamp cannot pull the time back) is over the TTL of the entry it could have read (the agent's latest earlier write: 1 h when it wrote ephemeral_1h tokens, else 5 min); `previous_message_not_found`, `unavailable`, `null` and absent diagnostics count as an expiry only through this test; else `model_changed` for a different recorded model; else `ttl_changed` for a different write tier than the entry; else `unexplained`.
- **recommender.ts**: 8 recommendation patterns (compact command, compaction prediction, idle compaction, duplicate reads, top consumers, MCP info, CLAUDE.md size, session habit) + fix prompt generator. "Messages until auto-compaction" projects the live window's growth per message since it started (`windowGrowth`: from the last compaction's `tokensAfter`, or the first turn's input; no projection under 4 messages). `buildCompactCommand` (used by `fix` block 3) and `recommendCompactCommand` (used by `analyze` priority-1) both delegate to `optimizer.ts:buildCompactFocus` so all three commands — `fix`, `analyze`, `optimize` — emit byte-identical `/compact focus "..."` strings on the same session. Top 5 consumers sizes each Read from its own tool_result (`indexToolResults` / `resultTokens` from waste-detector.ts, by tool_use id) and the compaction summary from its classified row. The CLAUDE.md size note is `FixPrompts.claudeMdNote`, shown beside the fix blocks, never inside the CLAUDE.md block
- **renderer.ts**: 8 render functions (dashboard, timeline, list, waste, fix, comparison, lost, trend). Bar chart guarantees ≥1 filled block for categories ≥1%
- **calibrator.ts**: /context parser, calibration storage, comparison. Exports `CRUSTS_DIR` (~/.claude-crusts). Parses both the current markdown table (`| Label | 21.1k | 2.1% |`, `k`/`m` suffixes, `**Tokens:** used / window` header, bucket rows scoped to the "Estimated usage by category" section so per-tool / memory / skills sub-tables are ignored) and the legacy colon format. `(deferred)` rows and the autocompact buffer are captured but excluded from `total_used`; `window_size` and `model` are exposed; the "System tools" row is persisted as `core_schema_tokens_override` (read via `loadCoreSchemaOverride()`), which the classifier prefers over any version-keyed schema constant. `parseTokensHeader` / `parseContextWindowSize` are exported for transcript-based window detection. `readPastedBlock` ends on two consecutive empty lines (the table contains single blank lines). Tests sandbox the file via `CRUSTS_CALIBRATION_DIR_OVERRIDE`.
- **trend.ts**: Cross-session trend tracking — append-only JSONL history, deduped by session id, sparkline + direction detection
- **comparator.ts**: Cross-session comparison engine with 5 auto-insight rules
- **html-report.ts**: Standalone HTML report generator (session + comparison modes)
- **md-report.ts**: Standalone Markdown report generator (session + comparison modes)
- **lost-detector.ts**: Compaction loss analysis — reconstructs what was dropped. Detects tool_use ID filenames and replaces with "Agent sub-task result". Extracts meaningful descriptions from agent/tool results
- **watcher.ts**: Live session monitor with compact dashboard, inline compaction line (flash effect on new compaction, settles to yellow), category labels `C R U Sys T St`
- **built-in-tools.ts**: core tool catalogue. `CORE_TOOL_NAMES` (20 always-loaded names, no per-tool token guesses; Task* and AskUserQuestion are version-dependent), `CORE_SCHEMA_TOKENS_BY_VERSION` (core schema cost per Claude Code version band: >=2.1.214 -> 20,500; 2.1.160+ -> 17,500; 2.1.150+ -> 15,000; else `LEGACY_CORE_SCHEMA_TOKENS` 9,055, which `TOTAL_BUILTIN_TOOL_TOKENS` aliases for back-compat), `resolveCoreSchemaTokens(version, override, legacy)` (calibration override > version table > legacy), and the deferred load costs `DEFERRED_BUILTIN_LOAD_TOKENS` 1,000 / `DEFERRED_MCP_LOAD_TOKENS` 330 charged per distinct tool at the ToolSearch result that loaded it. The classifier derives `toolBreakdown.loadedTools` = core names + tools invoked without a ToolSearch load + `loadedDeferred` (from `toolUseResult.matches` / `tool_reference` blocks); `deferredBuiltIn` / `deferredMcp` come from `deferred_tools_delta` attachment records and are never listed as loaded or unused. `isCrustsShellCall` treats `PowerShell` like `Bash` so Windows self-calls are trimmed
- **tui.ts**: Interactive REPL shell — session picker, command dispatch (analyze/waste/fix/copy/timeline/lost/status/compare/trend), readline-based prompt with session ID indicator, tab completion for commands + session IDs, clipboard copy for fix blocks
- **clipboard.ts**: Cross-platform clipboard utility — `clip` (Windows), `pbcopy` (macOS), `xclip`/`xsel` (Linux)
- **hooks.ts**: Claude Code hook integration. `enableHooks` / `disableHooks` / `hooksStatus` and the auto-inject trio edit `~/.claude/settings.json` (each takes a settings path, for tests). The status hook is `HOOK_COMMAND` (`claude-crusts status --hook`) on `HOOK_EVENT` (`Stop`), installed synchronous with a 30 s timeout: an async hook's systemMessage goes to Claude, not the person. `enable` removes the 0.8.1-and-earlier `claude-crusts status` entry on `Notification` (`LEGACY_HOOK_COMMAND` / `LEGACY_HOOK_EVENT`, matched exactly on that event only), where Claude Code discards a hook's `systemMessage` and stdout; `disable` removes both entries. `detectStatusHooks(settings)` returns `{installed, legacy}` for `hooks status` and the doctor. `enableHooks` installs nothing when `statusHookCommandProblem()` reports one: Claude Code runs the hook by name, so `claude-crusts --version`, run through the shell, must answer `STATUS_HOOK_SINCE` (0.8.2) or later (the check is a parameter, for tests). Every write first backs up settings.json to `~/.claude-crusts/backups/settings.json.<ts>.bak` (newest `SETTINGS_BACKUPS_KEPT` kept; `CRUSTS_BACKUP_DIR_OVERRIDE` for tests), removes only crusts' own commands (a group or event is dropped only when that removal emptied it), and is skipped when the file does not parse or `hooks` has the wrong shape. Runtime: `runStatusHook` (`status --hook`) reads the payload with `readHookPayload` (`HOOK_STDIN_TIMEOUT_MS`; stdin is paused and destroyed at the deadline, so an open pipe cannot hang the process), prints nothing when `stop_hook_active` is true, picks the session by `transcript_path`, then `session_id`, then the latest, and prints exactly `{"systemMessage": "<summarizeStatus line>"}`: never a `decision`, never exit 2, every error swallowed. `buildStatusSummary(sessionPath, cwd?)` builds config the way `analyze` does (`sessionProjectPath`, else the payload's cwd; the slug; observed MCP servers) and is shared with plain `status`. `autoInjectStatus` also counts the session summaries. Also manages `hooksEnabled` / `installedAt` in `~/.claude-crusts/config.json`.
- **statusline.ts**: Claude Code statusline integration — installs a `statusLine` entry that runs `claude-crusts statusline` on every refresh. Exposes `renderStatusline` (one-glyph + % output) and `readStatuslinePayload` (stdin JSON reader with fallback to null on any error — statusline must never break Claude Code); the payload's `model.id` and `context_window.context_window_size` are threaded into `classifySession` as `modelOverride` / `limitOverride`
- **model-context.ts**: Model-to-context-window resolution, the compaction model, and the shared usage helpers. `effectiveInput(usage)` = `input_tokens + cacheCreationTokens(usage) + cache_read_input_tokens`, where `cacheCreationTokens` takes the larger of the flat `cache_creation_input_tokens` and the nested `cache_creation.ephemeral_5m + ephemeral_1h` sum, except for zeroed copies (`isZeroedUsageCopy`: input, cache_creation_input, cache_read and output all 0), which a continuation file writes for the previous conversation's last turns while the nested breakdown keeps the old window; they carry no usage. Every "how big was the window on this turn" computation goes through it. `resolveContextLimitWithSignal(modelId, messages, {limitOverride, settingsModels, disable1m})` resolves the window from the full signal priority list: payload `limitOverride` > latest recorded `## Context Usage` (/context) record whose `**Model:**` line names this model family (`detectContextCommandWindow(messages, modelId)`; 200k/500k/1m all observed) > `CLAUDE_CODE_DISABLE_1M_CONTEXT` (200K) > model-id `[1m]` regex > settings.json model when its family matches the session model > usage above 200K (conclusive 1M) > native 1M (`getNativeContextLimit`, from Claude Code's model-config docs: Fable, Sonnet 5+, Haiku 5.5+, Opus 4.7+, Mythos 5+; IDs parsed by `parseClaudeModelId` as family + major + minor, date and variant tolerated) > 200K default (Opus 4.6, Sonnet 4.6, older). `signal` is `payload | context-command | disable-1m | model-id | settings | usage | native | default`. `resolveCompactionModel(limit, model, liveTokens, settings, cacheTtl)` returns `{trigger, autoCompactWindow, windowSource, bufferTokens, idle}`: trigger = min(auto-compact window, limit) - buffer (env > per-model `/autocompact` window > top-level `autoCompactWindow` > the window), null when auto-compaction is off; idle compaction applies when enabled, the latest cache write is not the 5-minute TTL (`latestCacheTtl`), and the live window is at or above the idle threshold. Claude Code strips `[1m]` from JSONL, so the settings/usage/native signals carry recorded sessions where the variant is gone.
- **optimizer.ts**: Ranked actionable fixes with ROI. `buildOptimizeReport` generates a sorted list of fixes (compact-focus, read-deny, CLAUDE.md rule append, MCP disable info, CLAUDE.md oversized warning), each tagged with estimated token savings. `FIX_KINDS` lists the kinds; `parseFixKinds` parses `--filter`, and `RENAMED_FIX_KINDS` maps the old `claudeignore` to `read-deny`. read-deny: reads inside the project of `node_modules/`, `.git/` and lock files (`package-lock.json`, `npm-shrinkwrap.json`, `pnpm-lock.yaml`, `yarn.lock`, `bun.lock`/`bun.lockb`, `Cargo.lock`, `poetry.lock`, `Pipfile.lock`) become any-depth `Read(/**/<folder>/**)` or `Read(/**/<lock file>)` rules for `permissions.deny` in `<project>/.claude/settings.local.json`. An output folder (`dist`, `build`, `.next`, `target`, matched case-sensitively) becomes a rule for the folder that was read (`Read(/packages/web/dist/**)`), proposed only when `gitOutputFolder` confirms it holds output (git ignores it or tracks nothing in it; no git, no rule), since a deny rule also blocks editing and those names often hold source (`OptimizeOptions.isOutputFolder` replaces the check in tests). Each read costs its own classified result row (`resultTokens`). The project folder is the session's (`AnalysisResult.projectPath`) unless `--project-path` names one; without one no file fix is offered. The claudemd-rule fix is offered only where the deny rules cannot apply (settings file invalid, or `--filter` without read-deny). Paths are matched relative to the project root; reads outside it and failed reads are skipped; rules already in the file are not proposed. `applyFix` handles the auto-apply pipeline: per-fix confirmation, backup to `~/.claude-crusts/backups/<filename>.<timestamp>.bak` (`backupFile`), clipboard fallback for non-file fixes. read-deny goes through `readDenySettings` (BOM stripped; a missing or blank file is fine; refuses a file that is not a JSON object, or whose `permissions` is not an object or `permissions.deny` not a list when present) and `mergeDenyRules` (keeps every other key and the existing rules, appends only missing ones), creates `.claude/` when missing and writes with `writeFileAtomic`; a second apply is a no-op. `pruneBackups` keeps only the last 10 backups per filename. `claudemd-oversized` compares `sessionClaudeMd` (every CLAUDE.md file the session loads, model tokens) with `claudeMdOversizedThreshold` and names the three largest; `buildCompactFocus` takes its targets from `compactTargets`.
- **doctor.ts**: Sanity-check command. Ten checks cover the crusts version, Claude Code install, settings.json validity, session discovery, transcript retention, hook/statusline install state, calibration presence, trend history readability, and optimize-backup-dir writability. Each check returns `pass | warn | fail`; `aggregateStatus` picks the worst of the three as the overall verdict. `checkTranscriptRetention(settings, context)` warns when `~/.claude/settings.json` has no `cleanupPeriodDays`, an invalid one, or one under `MIN_RETENTION_DAYS` (90), recommends `RECOMMENDED_RETENTION_DAYS` (365) and counts the session summaries; when `newestRecordedClaudeCodeVersion` (the last versioned record of the 5 most recently modified transcripts) is older than `LARGE_CLEANUP_PERIOD_FIXED_IN` (2.1.310) it warns on a value of `HUGE_CLEANUP_PERIOD_DAYS` (100 million) or more, where the cleanup cutoff leaves the Date range. A value must be a whole number, as Claude Code's schema requires. `readSettings` strips a UTF-8 BOM, as Claude Code does. Sessions are discovered once per run. The Hook integration check (`checkHookIntegration(settings, commandProblem?)`, via `detectStatusHooks`) passes with the Stop hook installed or none, and warns when the 0.8.1-and-earlier Notification entry is still installed or the installed hook's command would fail (`statusHookCommandProblem`).
- **config.ts**: Shared user-level config store at `~/.claude-crusts/config.json`. Exports `loadConfig` / `saveConfig` (merge-safe: sibling keys preserved on partial writes; atomic: temp file + rename, so concurrent hooks never tear the file), `loadWasteThresholds` (returns effective thresholds merging user overrides into `DEFAULT_WASTE_THRESHOLDS`), and `describeThresholdOverrides` (human-readable delta list used by `--verbose`). `hooks.ts` has been migrated to use these helpers so the hook state no longer clobbers the waste-thresholds key. `writeFileAtomic(target, content)` is the temp-file-plus-rename writer (creates the folder; the rename is retried on Windows EPERM/EBUSY/EACCES), shared by `saveConfig`, the optimizer's settings.local.json write and the session summaries. `crustsSessionsDir()` resolves `sessions/` next to config.json, so `CRUSTS_CONFIG_DIR_OVERRIDE` moves both.
- **session-diff.ts**: Intra-session diff engine. `computeSessionDiff(messages, config, sessionId, fromIndex, toIndex)` runs `classifySession` at two cutpoints and returns per-category deltas. Complements `comparator.ts` (which diffs two *different* sessions). Renderer prints a coloured cli-table with green/yellow highlights for negative/positive deltas.
- **bench.ts**: Measurement harness for `/compact` events. `runBenchCompact(session, options)` captures a BEFORE snapshot, tails the session JSONL for a `compact_boundary` record, then captures AFTER — replacing the fragile "paste-and-switch-window" PowerShell flow. Extracts "what survived" from the post-boundary `isCompactSummary` message via `extractFileRefs`, which uses a `FILE_EXTENSION_WHITELIST` so JS method calls like `Math.abs` / `console.log` don't pollute the survivor list. `compareBenchResults(a, b)` diffs two bench envelopes to produce `onlyInA` / `onlyInB` / `inBoth` sets — the A/B experiment payload. `reextractSummaryRefs(resultPath)` re-runs the extractor against the session JSONL so old bench outputs can be cleaned after the regex is tightened, without recompacting the session. Exit semantics: 0 on compact, 2 on timeout, 1 on error.
- **auto-inject.ts**: Hook-triggered fix injection. Installed as a `UserPromptSubmit` hook in Claude Code settings; runs on every prompt submit, which includes background-task reports, `/loop` iterations and cross-session messages. `promptSkipReason(prompt)` skips `/compact`, `/clear` (and its aliases `/reset`, `/new`), slash-command echoes and interrupts before the transcript parse. The hook builds config from the session's own project (`sessionProjectPath`, the folder the session started in, as `analyze` uses; else `payload.cwd`, which follows a mid-session `cd`; the slug; observed MCP servers). `shouldInject(breakdown, config, sessionId)` gate-keeps on `enabled`, usage ≥ `threshold` while that point comes before Claude Code's trigger (else the headroom gate: within max(20K, 10% of the auto-compact window) of `breakdown.compaction.trigger`), and a per-session min-gap (`autoInject.lastInjections`, the newest 50 sessions kept). When the gate opens, `buildInjectionText` synthesises a session-specific advisory with the `/compact focus "..."` from `compactCommandFor(waste)` and a "Why now" line naming this session's trigger and idle compaction, and `runAutoInject` emits it as `hookSpecificOutput.additionalContext` (for Claude) plus `systemMessage` (`buildUserNotice`, a one-line notice shown to the person whichever turn it rides on). Each injection is also appended to `~/.claude-crusts/auto-inject.log` (JSONL) via `writeInjectionLog` for audit/transparency — `readInjectionLog(limit?)` returns entries newest-first, skipping corrupt lines. Fire-and-forget: all errors swallowed so a bug never blocks the user's prompt. Opt-in via `hooks auto-inject enable`; audit history via `hooks auto-inject log`. The advisory's targets and its "reclaimable" figure come from `compactTargets(waste)`. Every analysed prompt, whether or not the gate opens, also updates the session's summary through `recordSessionSummary` (session-summary.ts); an advisory's log time is its `advisories.lastAt`.
- **session-summary.ts**: Per-session summaries that outlive Claude Code's transcripts (deleted after `cleanupPeriodDays`). `recordSessionSummary(observation, now?)` keeps `~/.claude-crusts/sessions/<sessionId>.json` (`crustsSessionsDir()`), schema v1 `{ v, sessionId, project, transcriptPath, firstSeen, lastSeen, claudeCodeVersion, model, contextLimit, autoCompactWindow, trigger, peakTokens, lastTokens, compactions: [{ at, trigger, idle, preTokens, postTokens, tokensAfter }], advisories: { count, lastAt } }`, built from the hook's breakdown (no extra parse). It writes when anything but `lastSeen` changed and otherwise refreshes `lastSeen` at most every `SUMMARY_REFRESH_MS`; returns `written | refreshed | unchanged | skipped | failed` and never throws. Only marker compactions are recorded (the token-drop fallback also fires on interleaved chains); compactions merge by boundary time + preTokens, the transcript's version wins, and ones the transcript no longer holds (`CLAUDE_CODE_TRANSCRIPT_LOCAL_GC` trims history before a compaction) are kept. `peakTokens` is the max of the live windows seen and every preTokens; `firstSeen` is the hook's first write; `claudeCodeVersion` is the session's first recorded version and stays put. A corrupt file (bad JSON, wrong shape, another session's id) is replaced; a file with a newer `v`, one that cannot be read, or an id that is not a safe file name is skipped. `loadSessionSummaries()` returns every valid summary, most recently seen first; `hooks auto-inject status` and `doctor` count them.
- **completion.ts**: Shell-completion script emitters. `generateCompletionScript(shell)` dispatches to `generateBashCompletion` / `generateZshCompletion` / `generatePowerShellCompletion`, each returning a script text the user sources from their shell profile. Scripts cover top-level subcommand completion and session-id prefix completion for the dozen commands that take `[session-id]`. Session IDs are sourced via `claude-crusts completion ids` — an internal subcommand that prints one ID per line so completion scripts don't need jq, awk, or PowerShell JSON parsing. `SUBCOMMANDS` and `SESSION_ID_SUBCOMMANDS` lists are hard-coded here and must be kept in sync with `index.ts` command additions; `tests/completion.test.ts` guards against drift on the core command names.
- **.claude/commands/crusts.md**: Custom slash command — runs `npx claude-crusts analyze --json` and gives actionable advice

## Key Technical Decisions

**Compaction detection** — marker-based, not heuristic:
- Primary: `subtype === 'compact_boundary'` with `compactMetadata.preTokens`
- Also detects: `isCompactSummary: true` (classified as System), `model: '<synthetic>'` (filtered at parse time)
- Fallback: 30K token drop between consecutive assistants (only if no markers)
- Records after a boundary can still describe the OLD window: a continuation file repeats the previous conversation's last turns (timestamped before the boundary, usage zeroed), and an in-flight turn can finish after it. Neither is a live turn; `firstLiveIndex` marks the first one that is.
- `compactMetadata.postTokens` is Claude Code's chars/4 count of what it wrote after compacting (summary, re-attached files, command records), without the fixed context; the first live turn sat 45K-77K above it on real sessions (median about 59K) and 142K once with a large preserved segment. It is never used as the window size on its own. Before the first live turn the window is estimated as postTokens × the session model's tokenizer factor + the fixed context (with the System bucket's system-prompt figure) + the re-attached files recorded so far + the files Claude Code re-attached but has not recorded yet (`pendingReattachments`, also in Retrieved): a median 6.2% from the next request on 50 real compactions (worst 25.5%). The recorded re-attached files are counted a second time (postTokens already holds them), which stands in for context crusts does not itemize after a compaction, such as the re-sent skills listing; calibrating that is planned. When the file holds no `prompt_snapshot` and no anchor yet (a continuation file's first prompt), the system prompt is missing from the fixed context, so the estimate runs low there. The timeline marks this size with `~` until the next response.
- Idle compactions (Claude Code 2.1.286+ by reports, announced in 2.1.299; a 200K+ conversation idle about 54 minutes, one-hour cache) are labelled from the "Compacted while idle" or "Compacted after an hour idle" notice; 2.1.289 recorded them with trigger `manual`, 2.1.296 and later `auto`.

**Token estimation** — content-aware:
- Assistant messages: `output_tokens` from API (exact)
- Code content: chars / 3.3 (detected via `CODE_PATTERN` regex)
- English text: chars / 4.0
- Includes: tool block metadata (IDs, names), recursive sub-blocks (each estimated with its own divisor, then added as tokens)
- Media: image blocks cost a flat `IMAGE_BLOCK_TOKENS` (1,500); document blocks cost base64 length / 4
- NOT counted: `block.signature`. Thinking text is never persisted in the JSONL (every thinking block has `thinking: ''`); the signature is an opaque verification token, not content

**Derived overhead** — per-session, not hardcoded:
- Internal system prompt: the anchor turn's effective input − known components (CLAUDE.md + core tool schemas [version-keyed, calibration-pinned; see built-in-tools.ts] + memory + skills [skill_listing attachment preferred, else discovery, fallback 476] + every recorded window record before the anchor: user-role records, attachments, and for a compaction window the summary and carried-over content). The anchor is the first turn whose whole window the file records: the fresh first turn, else (a continuation file that opens with a boundary) the first live turn after a boundary. Accepted range: 1,000 up to the smallest live window (every live turn carries the fixed context; the old file-first anchor attributed a whole previous conversation, 790,912 tokens). CLAUDE.md and memory come from the session's `instructions` attachment when recorded. Semantics: "Claude Code fixed context not present in the JSONL".
- Message framing: median of ≤20 consecutive assistant pair deltas from post-compaction window. Range 0-50 tokens/msg. Distributed proportionally across categories.

**Range- and edit-aware duplicate reads** (`detectDuplicateReads`):
- A Read covers the lines it delivered: `toolUseResult.file.startLine`/`numLines` on main-session records, else the number that prefixes every result line (a tab, a `:` in 2.1.3xx for tab-indented files, or the padded arrow before 2.1.86). `offset` is the 1-based first line. A call without `limit` stops at Claude Code's default or token cap, so the delivered lines are used, not the input. Images, PDFs and notebooks cover the whole file (or the `pages` asked for) and are compared by content.
- An earlier read is waste only for the lines a later read of the same file delivered again, sized as that share of its result tokens (lines weighed by text length); overlapping later reads count once.
- Not waste: an Edit/Write/MultiEdit/NotebookEdit call of the file in between (failed calls too; NotebookEdit's `notebook_path` is read); different text for the same lines; later reads that delivered nothing. The last covers Claude Code's unchanged-file stub (`toolUseResult.type: 'file_unchanged'`, or text starting `File unchanged since last read`, `Wasted call` or `<system-reminder>This file is already in your context`; Claude Code stubs a re-read with the same offset and limit as the previous read of an unchanged file, and a Read of a CLAUDE.md or memory file it loaded at startup (the `<system-reminder>` prefix)), errors, and notices of 400 chars or less without numbered lines.
- An earlier read counts once its repeated share reaches `MIN_DUPLICATE_TOKENS` (100), so the few lines where pages meet never add up to an item. An item whose earlier reads were only partly delivered again is `compactable: false` and no /compact target: "keep only latest read" would drop lines read once. The recommender, fix prompts, optimizer and auto-inject parse `"<file>" read N times` and `reads at <locations> are`, so locations (`#a`, `#b lines x-y`, up to 8 then `and N more`) never contain ')'.
- Read tokens come from the call's own tool_result, found by tool_use id (stale reads use the same sizing). Only the analysed rows are scanned.

**Read deny rules, not ignore files**: Claude Code reads no `.claudeignore` (its permissions docs say the file has no effect), so the read-deny fix writes `permissions.deny` rules. Patterns use the permission path syntax, which is gitignore syntax. `/` anchors at the settings source, which for `.claude/settings.local.json` is the session's primary working directory, and `**` matches any depth. `./x` and bare `x` resolve against Claude's current directory, which follows a `cd` (checked in the 2.1.310 binary), so crusts writes `Read(/**/node_modules/**)`, not `Read(./node_modules/**)`. A Read deny rule also blocks Edit and Write on the path (2.1.228+) and leaves it out of Grep/Glob results and @-mentions. On macOS and Linux git repos, Claude Code 2.1.211+ keeps its own local file at the repository root (the main checkout for worktrees) and still reads a copy in the starting directory; on Windows the file sits in the starting directory.

**CLAUDE.md size from the session's own record**: the `oversized_system` waste item, the recommendation, the fix prompt's note, the `claudemd-oversized` fix and the top-consumers fallbacks read one figure, `breakdown.claudeMd`, in the session model's tokens. A 2.1.268+ session records the files it loaded, so a parent folder's CLAUDE.md, CLAUDE.local.md and `@` imports (an imported AGENTS.md included) count; up to 0.8.1 the disk scan counted the project's settings.json, which is never sent, and missed parent folders. The advice follows Claude Code's memory docs: CLAUDE.local.md and imports load with CLAUDE.md, so only path-scoped rules (`.claude/rules/` with `paths:`) and a subfolder's CLAUDE.md load on demand. CLAUDE.md is read again after every compaction, so it is never a /compact target and never counts toward a compact's savings (`compactTargets`).

**Auto-trim** — 3-phase backward walk:
1. Strip trailing CRUSTS Bash calls and tool_results
2. Strip preceding assistant text/thinking (same turn)
3. Strip the triggering user prompt

**MCP tools**: `MCP_TOKENS_PER_TOOL = 0` for configured-but-deferred servers. Deferred schemas (MCP and deferred built-ins) cost 0 until a `ToolSearch` call loads them; each load is then charged once per distinct tool at the result index (~330 per MCP tool, ~1,000 per deferred built-in).

**Dynamic context limit** — resolved per-session via `resolveContextLimitWithSignal(model, messages, {limitOverride, settingsModels, disable1m})` in `model-context.ts`, over every span of the current model family (evidence from an earlier run of the same model counts; another model's does not). Priority (first hit wins): (1) live payload `context_window.context_window_size`; (2) latest `## Context Usage` record for this model in the transcript (a free integer: 200k/500k/1m all observed); (3) `CLAUDE_CODE_DISABLE_1M_CONTEXT` (200K); (4) model-ID `[1m]` regex; (5) settings.json `[1m]` model whose family matches the session model; (6) usage heuristic: any turn's effective input above 200K proves 1M (a 200K model would have errored); (7) native 1M per Claude Code's docs (Fable, Sonnet 5+, Haiku 5.5+, Opus 4.7+, Mythos 5+, point releases and dated IDs included); (8) 200K default (Opus 4.6, Sonnet 4.6, older and unrecognised IDs).

**Compaction model** — `breakdown.compaction` (from `resolveCompactionModel`), matching Claude Code 2.1.302: the token trigger is the auto-compact window minus the 33K buffer, where the window is `CLAUDE_CODE_AUTO_COMPACT_WINDOW` (floored at 100K, capped at 1M; `k`/`M` suffixes from 2.1.304, while earlier versions read `200k` as the 100K floor, kept as `envAutoCompactWindowLegacy` and chosen by the session's version), else the per-model window `/autocompact` saves under `modelSettings` ('auto' = the model default), else the top-level `autoCompactWindow`, else the context window (capped at it). Settings files layer user < project < local, and a file's top-level window replaces the per-model windows below it; window values outside 100K-1M are ignored. `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` fires at min(floor((window - 20K) * pct / 100), window - buffer). Null when auto-compaction is off (`autoCompactEnabled: false`, `DISABLE_AUTO_COMPACT`, `DISABLE_COMPACT`). Idle compaction (`IDLE_COMPACTION_SINCE`, 2.1.286) applies when it is on, the session's latest cache write was not the 5-minute TTL, and the live window is at or above `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` (200K default); it is rolled out in stages, so crusts says "may". Recommendations, the timeline, the default inject gate and the advisory all read this model.

**Model ID sources** — Claude Code **strips the `[1m]` variant** from the `model` field it writes to JSONL, so for recorded sessions the regex never matches and the usage heuristic is load-bearing. The live statusline path sidesteps this: `classifySession(messages, config, untilIndex, modelOverride, limitOverride)` accepts an optional `modelOverride` (threaded from the stdin payload's `model.id`, which Claude Code preserves with the variant) and an optional `limitOverride` (the payload's `context_window.context_window_size`, which wins over every recorded signal). Result: statusline on a fresh 1M session correctly shows small percentages even before any usage crosses 200K.

**Multi-model sessions (model switching)** — when a user switches Claude models mid-session, `computeModelHistory` in `classifier.ts` builds a `ModelHistory` with one `ModelSegment` per contiguous same-model run. `breakdown.model` is the LAST non-synthetic model (current state); the first model is preserved in `modelHistory.segments[0]`. The analyze header appends "(switched from X)" when `switchCount > 0`. The `models` command renders the full per-segment table with input/output/cache-read/cache-write token sums from `usage.*` (exact, not estimated).

**Health label reads current, not lifetime** — `recommender.ts` passes `breakdown.currentContext?.usage_percentage ?? breakdown.usage_percentage` to `getContextHealth`. Using `breakdown.usage_percentage` alone was a bug: post-compaction sessions accumulate lifetime tokens that routinely exceed the context limit, reading as "critical" even when the live window is cold. The fallback path preserves correct behaviour for pre-compaction sessions where `currentContext` is undefined.

**Window reconciliation (v0.8.0)** — bucket `tokens` are scaled (floor + remainder to the largest bucket) so their sum equals the API window `total_tokens` exactly; the raw classifier estimate is preserved per bucket as `contentTokens`. `currentContext` buckets are always reconciled when usage data exists; lifetime buckets are reconciled only when the session never compacted (a compacted lifetime is a cumulative-flow number, kept on the content basis). Guard band: if the scale factor falls outside [0.7, 1.4] the buckets stay on the content basis (`reconciliation.basis === 'content'`) and the scale is printed under `--verbose`, keeping estimator drift visible instead of masking it. Trend records carry `bucketBasis` (`window` or `content`; blank for pre-0.8 records).

## Waste Detection Rules

1. **Stale reads**: file read >15 messages ago, filename not referenced since
2. **Duplicate reads**: lines a later Read of the same file delivered again, with no edit call and no content change in between; sized by the repeated share; an earlier read under 100 repeated tokens and Claude Code's unchanged-file stubs are not reported; partial repeats are no /compact target
3. **Oversized CLAUDE.md** (`oversized_system`): the CLAUDE.md files the session loads at startup (`breakdown.claudeMd`) above 1,500 tokens in the session model's tokens; never a /compact target
4. **Resolved exchanges**: short user messages (<100 chars) containing resolution phrases, >500 tokens in preceding 10 messages
5. **Cache overhead** (cache re-writes): requests that wrote most of the previously cached prefix again (expiry, a model, system, tools or messages change, or a TTL switch), counted once per API response, with the first request and the first post-compaction request excluded. Flagged when re-writes reach 25% of the session's cache-write tokens and 50,000 tokens. Cache reads are never counted. Severity info, `estimated_tokens` 0
6. **Unused results**: non-retrieval tool results >200 chars where assistant text <50 chars in next 5 messages

Post-compaction aware: only analyzes messages after `currentContext.startIndex`, except the cache rule, which measures the whole analysed session (cache writes are billed across compactions).

## Development Workflow — Regression Coverage

Every non-trivial change must land with unit test coverage.

**When you add a new feature, you must:**

1. **Add unit tests.** Every new module or exported function lands with coverage in `tests/*.test.ts`. `bun test` runs in about 10 seconds — the fast feedback loop.
2. **Read the output critically.** Exit 0 from the suite is necessary but not sufficient. When running commands manually, eyeball: category-sum consistency with displayed totals, `Context health:` label matching the `%` shown, correct model in the header (LAST non-synthetic assistant), no NaN / Infinity / undefined leaking into user-facing numbers.
3. **When a feature has a numeric invariant worth enforcing**, add a unit test that asserts the invariant (see `tests/model-history.test.ts` for the post-compaction-health pattern and `tests/classifier.test.ts` for the API-effective-input invariants).

**Cadence:**

- Before any `git commit` on a feature branch: `bun test` must pass (`bun run typecheck` too).
- Before moving the `v*` tag or pushing: do a manual `analyze` on a known-real session and eyeball the numbers. Unit tests catch most regressions, but a live session is the only way to notice display-level weirdness.
- Before any `git push origin v*` or `npm publish`: a second live run on a session with compactions in it, confirming `TOTAL`, `FREE`, `usage_percentage`, and `Context health:` are all consistent with each other and bounded by `context_limit`.

## Known Issues

- Interleaved concurrent-session chains: a JSONL where several prompt chains interleave (parallel Claude Code panes on one session file) shows unmarked >30K drops between consecutive assistants. Chain reconstruction from `last-prompt.leafUuid` is deferred (v0.8.0 mitigates it: phantom rows are dropped at parse time and compaction detection prefers markers over the drop heuristic)
- Subagent session files are not discovered or merged into the parent analysis (`--include-subagents` deferred)
- Attachment records are assumed to persist in the window on later turns; if Claude Code re-injects some types per turn (task_reminder is the big one), those buckets can over-count. Settling evidence: framing-delta sign across turns with large task reminders
- `CORE_SCHEMA_TOKENS_BY_VERSION` values are minimums read off /context rows that may already include ToolSearch-loaded built-ins; a saved `calibrate` override is always the authority
- Text divisors (4.0 / 3.3 chars per token) were measured on the older tokenizer; estimates scale 1.3x on Claude 4.7+ (Anthropic's figure), which brought the median bucket scale on the recorded /context outputs to 1.06 (67 of them, none outside the guard band). Dense content (tool-name lists, JSON) still runs low. 2.1.268+ transcripts record the fixed context (`prompt_snapshot`) and 2.1.300 records every request (`api-request-shape` + `api-request-blob`), which allows exact composition (planned)
- Kept thinking dropped at a model switch or a cache-prefix mismatch (`thinking_drop` attachments) still counts in Conversation
- The skills listing re-sent after a compaction is not recorded, so post-compaction views can miss it (about 7K tokens)
- The Stop status hook parses the whole transcript after every response (about 1 s at 186 MB; an incremental parse is planned). It reads what Claude Code has flushed by then; Claude Code's docs say the final message may not be in the transcript yet at Stop time on some versions, and then the notice shows the window as of the previous API call. Installs from 0.8.1 and earlier stay on the Notification event, where they show nothing, until `hooks enable` is run again (`hooks status` and `doctor` flag them)
- `statusline install|uninstall` still write settings.json without a backup, and `statusline install` rewrites a settings.json that does not parse from `{}` (`uninstall` leaves such a file alone)
- The cache rule reads the main transcript only. Current Claude Code writes subagent requests (their own cache, 5-minute TTL by default) to separate files under `<session>/subagents/`, which crusts does not read, so they are not counted. Only sidechain records inside the analysed file form their own chains and make the advice name `subagentPromptCacheTtl`; the author's transcripts from 2.1.214 on hold none. Send times come from the record written before each request, so a gap within about a minute of the TTL can land on either side
- Session summaries are written on prompt submit by the auto-inject hook, so a session's last response (after its last prompt) is not in its summary, and sessions run without the hook enabled get none
- The retention check reads `cleanupPeriodDays` from `~/.claude/settings.json` only; a managed or project value (which wins) and `CLAUDE_CONFIG_DIR` are not seen
- The auto-inject hook runs only on prompt submit: a crossing inside a long autonomous turn is advised at the next prompt, and an idle compaction, which happens while no prompt arrives, gets no advisory first
- The per-launch `claude --autocompact` flag and any server-side auto-compact window are invisible to crusts; the settings files and environment it can read are covered
- Between a compaction and the first response after it, TOTAL is an estimate (see Compaction detection); the records after the first prompt (the prompt, a command's skill body) are not yet added to it. Its second count of the re-attached files stands in for context crusts does not itemize after a compaction (the re-sent skills listing among it), which the buckets cannot attribute: 4 of 48 views right after /compact on real sessions stay outside the guard band
